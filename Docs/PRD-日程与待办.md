## 1. 背景与问题

DeskMate目前是一个纯本地 Markdown 便签工具，核心资产是「随手呼出」：全局快捷键弹便签、磁贴钉桌面、内容即 `.md` 文件。用户实际上已经在拿它当待办用——用 `- [ ]` 手写清单、把今日事项钉成磁贴、把临时灵感丢进便签。

但这套用法有三处硬伤：

1. **没有时间维度**。便签不知道「今天」「明天」，不会提醒，过期事项只能靠人眼盯。
2. **完成状态是文本**，不是数据。勾选框只改 Markdown 字符，无法统计、无法筛选、无法跨笔记汇总。
3. **待办和日程割裂**。用户要么在笔记里记「下周三 15:00 评审」，要么在系统日历里再建一次，信息重复且容易漏。

同时，主流待办/日历产品（滴答清单、Microsoft To Do、Fantastical）功能完整但都偏「重」：需要账号、引导流程长、启动慢。DeskMate的机会不是做另一个全能 TODO，而是**把日程与待办放进一个已经随手可得的本地窗口里**，保持零账号、零同步、零学习成本。

### 1.1 为什么是现在

- 便签/磁贴已经建立了「桌面常驻」的使用习惯，加待办是顺着习惯延长，而不是另起产品。
- 现有存储层（原子写、损坏重建、数据目录迁移）已经能承载结构化数据，改造成本可控。
- 不做云同步，就不必面对账号、冲突合并、服务端成本三座大山。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标                         | 判断标准                                                         |
| ---- | ---------------------------- | ---------------------------------------------------------------- |
| G1   | 用户能在 3 秒内记下一条待办   | 全局快捷键 → 输入 → 回车，全程不离开当前应用                     |
| G2   | 待办与日程在同一个界面闭环   | 「今天有什么」一屏看完，勾选、改期、看详情不需要切换窗口         |
| G3   | 提醒可靠且不打扰             | 到点通知误差 ≤ 60 秒；同日多条提醒可合并；支持稍后提醒            |
| G4   | 数据仍然属于用户             | 全部落本地明文文件，可读、可备份、可导出，卸载不锁死             |
| G5   | 不拖慢现有体验               | 冷启动无额外网络请求，笔记编辑路径无回归，空闲内存增幅 < 40 MB   |

### 2.2 非目标（本版本明确不做）

- 账号体系、云同步、多设备漫游。
- 团队协作、共享清单、会议邀请（iCal 订阅也暂不做）。
- 甘特图、任务依赖、工时统计等项目管理的重型能力。
- 农历、节假日调休、跨时区会议排期。
- AI 排程 / 自然语言大模型解析（快速添加走本地规则，见 6.4）。

## 3. 目标用户与场景

**主要用户**：已经在用DeskMate记事、希望少装一个 App 的人。特征是想快速记、不想维护系统。

### 场景 A：临时记事顺手变成待办

> 下午开会时，小林用 `Ctrl+Space` 弹出便签，写下「周五前把报价单发给张工」。她直接按 `Ctrl+Enter`（或点「存为待办」），这条内容进了待办清单，并识别出「周五」为截止日。会议结束后她关掉便签，桌面磁贴上显示今天还剩 3 项。

### 场景 B：早上看一眼今天

> 小周开机后DeskMate在托盘常驻。点托盘图标，菜单第一行显示「今日待办 4 项」。打开主窗口切到「日程」，周视图里 10:00 有评审、15:30 有牙医；右侧待办栏按「逾期 / 今天 / 明天」分组，逾期的两条标红。

### 场景 C：勾掉一项，明天自动再来

> 小陈的「每日复盘」是重复待办。他今晚勾完，列表里立刻出现明天的同一条，完成记录仍留在「已完成」里可查。

### 场景 D：笔记里的清单不再孤岛

> 小许的会议笔记里有 5 条 `- [ ]` 行动项。他在笔记工具栏点「提取待办」，5 条进入收件箱并带上来源笔记链接；点待办上的来源标记可以跳回原笔记对应行。

## 4. 产品原则

1. **零配置可用**：首次打开就有「今天 / 本周 / 全部」三个默认视图，不强制建清单、不强制设提醒。
2. **就地创建**：任何能看到日期或列表的地方都能直接新建，不弹全屏表单。
3. **键盘优先**：新建、完成、改期、切视图都有快捷键；鼠标是加速器而非唯一入口。
4. **数据可带走**：`.md` 笔记保持原样；待办与日程是单个 JSON，可直接备份；导出 Markdown / ICS 不收费、不设限。
5. **不打扰**：默认只对「有具体时间的日程」提醒；待办默认不响铃，只在托盘与界面显示；免打扰时段可配。

## 5. 信息架构

```
DeskMate主窗口
├── 笔记（现有）
│   ├── 分类 / 外部文件
│   └── 编辑器（编辑 / 分栏 / 预览）
├── 日程（新）
│   ├── 月视图 / 周视图
│   ├── 迷你月历 + 日期跳转
│   └── 事件详情抽屉
└── 待办（新）
    ├── 智能清单：今天 / 明天 / 本周 / 逾期 / 全部 / 已完成
    ├── 标签筛选
    └── 待办详情抽屉

独立入口
├── 快速添加浮窗（全局快捷键，P1）
├── 托盘菜单：今日待办数 / 快速添加 / 打开日程
├── 便签窗口第三个页签：今日待办（P1）
└── 今日待办磁贴（P1）
```

**边界定义**（避免同一件事被记两次）：

- **日程** = 占据一个时间块的事，有开始/结束，可能重复。例：周三 15:00 评审、周五全天出差。
- **待办** = 需要在某个时间点前完成的事，可以只有日期、也可以没有日期。例：周五前交报价单。
- 两者可互转：日程结束后可生成「写纪要」待办；待办设了具体起止时间可升级为日程（P1）。

导航采用**工作区切换**而不是新开窗口：主窗口标题栏左侧放「笔记 / 日程 / 待办」三段切换，切换时保留各自滚动位置与选中项。理由：用户的心智是「一个DeskMate」，不是三个应用。

## 6. 功能需求

优先级：P0 = v1.3.0 必须；P1 = v1.3.x 迭代；P2 = 后续版本。

### 6.1 待办（P0）

| 编号 | 需求             | 说明                                                                 | 验收标准                                                     |
| ---- | ---------------- | -------------------------------------------------------------------- | ------------------------------------------------------------ |
| T-01 | 创建待办         | 标题必填；可选日期、时间、优先级、标签、备注、提醒                   | 列表顶部输入框回车即建；不填日期落入「全部」                 |
| T-02 | 完成 / 取消完成  | 勾选即完成，记录完成时间；可撤销                                     | 勾选后 300ms 内划掉并移到「已完成」；`Ctrl+Z` 可撤销         |
| T-03 | 编辑             | 行内改标题；详情抽屉改其余字段                                       | 失焦自动保存；保存失败有 Toast 且不丢输入                    |
| T-04 | 删除             | 二次确认可关闭；删除进回收站（复用现有删除策略）                     | 删除后 5 秒内可撤销 Toast                                    |
| T-05 | 优先级           | 无 / 低 / 中 / 高，四档；用颜色条与排序体现                          | 高优先级在列表内靠前；颜色在明暗主题下对比度 ≥ 3:1           |
| T-06 | 日期与时间       | 支持「仅日期」与「日期 + 时间」；仅日期按全天处理                     | 仅日期不显示具体时刻；跨天判断以本地 00:00 为界              |
| T-07 | 标签             | 自由输入，逗号/回车分词；可筛选；标签自动补全                         | 同一标签大小写不敏感去重；删除标签不影响待办                 |
| T-08 | 智能清单         | 今天 / 明天 / 本周 / 逾期 / 全部 / 已完成                             | 计数实时更新；「本周」按设置项周起始日计算                   |
| T-09 | 排序             | 手动拖拽排序；默认按「逾期 → 今天 → 有日期 → 无日期 → 已完成」         | 拖拽后顺序持久化；刷新与重开窗口保持一致                     |
| T-10 | 搜索             | 标题、备注、标签模糊匹配                                             | 输入即时过滤；无结果有空状态                                 |
| T-11 | 批量操作（P1）   | 多选后完成 / 改期 / 删除 / 加标签                                     | Shift 连选、Ctrl 点选                                        |
| T-12 | 重复待办（P1）   | 每天 / 每周指定星期 / 每月指定日 / 每年；完成后生成下一实例           | 完成时下一实例日期正确；「每月 31 日」在小月落到当月最后一天 |

**列表行交互**：单击选中并展开右侧详情；勾选框在左；标题双击进入行内编辑；右侧显示日期与优先级；右键菜单为「改期 / 设为今天 / 加标签 / 转为日程 / 删除」。

### 6.4 快速添加（P1）

- 入口：全局快捷键 `Ctrl+Shift+Space`（可改，复用现有快捷键录制器）；托盘菜单「快速添加」；主窗口内按 `N`。
- 浮窗尺寸约 560 × 120，无边框、置顶、失焦即关闭，回车保存，`Esc` 取消。
- 解析规则（本地正则，按顺序消费）：

| 语法           | 示例                     | 结果                     |
| -------------- | ------------------------ | ------------------------ |
| 标签           | `#工作 #Q4`              | tags: 工作, Q4           |
| 优先级         | `!` / `!!` / `!!!`       | 低 / 中 / 高             |
| 重复           | `每天` `每周三` `每月1号` | recurrence               |
| 提醒           | `提前30分钟`             | remindMinutes: 30        |
| 时间           | `15:00` `下午3点` `晚8点` | dueAt 的时间部分         |
| 日期           | `今天` `明天` `周五` `11月8日` `2026-11-08` | dueDate / dueAt |
| 剩余文本       | `交报价单`               | title                    |

- 解析结果以 chips 形式显示在输入框下方，可点击修改；**解析失败不阻断保存**，整句作为标题、不设日期，并提示「未识别日期」。
- 输入框上方切换「待办 / 日程」，日程模式必须解析出日期，否则提示补充。

### 6.9 课程表（v0.2 增补）

- **定位**：周课表是「重复发生的时间块」的轻量表达，独立于日程事件，不参与提醒与冲突检测。
- **视图**：周一至周日 × 第 1–12 节网格；每节展示开始/结束时刻，课程块显示名称、地点、具体时刻、周次与待完成作业数，按颜色区分。**日历月视图与桌面「今日日程」小窗也会显示课程**（只读，点击打开课程抽屉；小窗底部提示「周一有 N 节课」）。
- **每节时刻**：课程表设置中可逐节配置开始/结束时间，默认按常见高校作息填充，可一键恢复默认。
- **学期与周次**：设置「学期开始日期」后，按本地日期推算「第 N 周」；顶部与侧栏展示当前周，可切换「仅本周」过滤课程（解析 `1-16周`、`1-8,10-16周`、`单周`、`双周` 等写法，无法解析则视为每周）。
- **录入**：
  - 手动：点空白格新增，或点课程块编辑；字段为课程名、星期、开始/结束节、地点、教师、周次、颜色、备注。
  - **课表文件（v0.8）**：直接选择教务系统导出的 `.xls` / `.xlsx`（≤10 MB），不需要复制粘贴。解析器自动定位含「星期一…星期日」的表头行，按「课程名/(节次)周次/校区/地点/教师/…」拆分每个格子；同一格多门课按换行拆分；同课程同星期的重复行合并周次并记录地点变动；`1-3周(单),4-8周`、`第3周` 等写法规范化为现有匹配器可用的 `1,3,4-8周`。无法解析的格子收集为 warnings，导入前显示课程数、工作表名与逐行预览。
  - **文字粘贴（v0.6）**：粘贴任意格式课表文字，每行一门课、字段顺序不限；支持「周一 / 星期三 / Mon」「1-2节 / 第5节 / 第3节」「1-16周 / 1-8,10-16周 / 单周 / 双周」「@教室」「张老师」等写法，整段为 TSV/CSV 时自动回退到表格解析器。纯函数解析 + 23 条单测。
  - 图片导入在 v0.7 已移除：系统 OCR 对课表截图的识别质量不稳定，保留表格与文字两种可校对入口。
- **课程内任务**：每门课可添加「作业 / 待办 / 提醒」，支持标题、截止日期与时间、提交平台（作业）；这些条目复用待办清单，因此会进入今天/本周/逾期等智能清单，可勾选完成、删除；课程块右上角显示未完成数量。
- **边界**：单门课只能落在一天、一段连续节次；「提醒」目前是带时间的待办项，不触发系统通知。
- **验收**：用真实教务系统导出的 .xls 导入 16 门课不重复、不丢字段（含单双周与地点变更）；设置学期后当前周与课程过滤正确；课程作业出现在对应日期的待办中；删除课程不影响日程；切换数据目录后课程与设置一起迁移；文件与文字两种录入方式共用同一套预览与逐行纠错。

### 6.10 每日必做（v0.2 增补）

- **定位**：每天重置的习惯清单，独立于待办，不进入「今天 / 本周」等智能清单。
- **能力**：新增/编辑/停用/删除模板；今日清单勾选；今日进度与近 7 天完成度；侧栏显示今日进度。
- **规则**：勾选记录按本地日期保存；删除模板会清除其历史勾选；停用后不再出现在今日清单但保留历史。
- **验收**：跨天自动重置；重启后当天勾选保留；删除模板后历史进度不残留。

### 6.11 快速待办小窗（v0.3 增补）

- **入口**：全局快捷键（默认 `Ctrl+Shift+Space`，macOS `Command+Shift+Space`），可在设置中修改或清空。
- **形态**：460 × 218 无边框置顶小窗，跟随鼠标位置出现；标题输入 + 今天/明天/后天/无日期四个快捷日期；`Enter` 保存并关闭，`Esc` 关闭。
- **数据**：创建为普通待办，主窗口通过事件自动刷新；小窗隐藏复用，不重复创建窗口。
- **边界**：只支持标题与日期，不在此处设置课程、平台、优先级；这些留给主窗口的待办详情。
- **验收**：快捷键在任意应用前台都能呼出；保存后主窗口「今天」列表立即可见；快捷键与其他两个全局快捷键重复时保存配置给出明确错误。

### 6.12 系统提醒（v0.4 增补）

- **调度**：Rust 后台线程每 30 秒扫描一次 `agenda` 快照，不依赖窗口是否可见；系统通知由 `tauri-plugin-notification` 发出，同时广播 `agenda-reminder` 事件驱动应用内提醒条。
- **范围**：有 `dueAt` 的未完成待办、仅日期的待办（默认当天 09:00）、课程内「提醒」类型的待办（复用待办数据）、非全天日程（开始前 N 分钟）；全天日程按开始日 09:00 提醒。
- **自定义提前量**：`Todo.remindMinutes` 覆盖全局默认值，来自快速添加的「提前30分钟」语法；全局默认可在提醒设置中选 0/5/10/15/30/60 分钟。
- **生命周期**：触发过的 key 持久化到 `agenda/reminders.json`，重启不重复弹；超过 30 分钟的过期提醒只计入已处理、不补弹；免打扰时段内静默且延后补发；提醒条提供「查看 / 5 分钟后 / 1 小时后 / 今天不再提醒」。
- **降级**：便携版 Windows 无包身份导致系统通知不可用时，仍显示应用内提醒条；点击「查看」跳到对应待办或日程抽屉。
- **设置**：启用开关、待办提醒开关、默认提前量、免打扰起止时间、自动生成每日回顾开关。

### 6.13 快速添加语法（v0.4 增补）

- 在快速待办小窗输入时实时解析，结果以 chips 展示；保存时映射到 `TodoInput`。纯本地正则、无副作用、不联网、不调 LLM。日期快捷项为「今天 / 明天 / 后天 / 无日期 / 自定义」，选自定义时展开日期选择器，可选任意日期（有输入时间时自动组合）。
- 支持 `#标签`（可多个、去重）、`!` / `!!` / `!!!` 优先级、`今天/明天/后天/大后天/周五/下周一/11月8日/2026-11-08/11/8` 日期、`15:00/下午3点/晚8点/3点半` 时间、`提前30分钟/提前1小时` 提醒提前量。
- 日期与时间组合成 `dueAt`；只有时间时默认今天；只有日期时保留 `dueDate`。已过去的月日自动指向明年。
- `每天/每周三/每月1号` 等重复语法可识别并提示「重复规则暂未支持」，按普通待办保存；解析失败不阻断保存，整句作为标题。
- 小窗高度由 218 调整为 252，容纳 chips 与解析提示。

### 6.14 每日回顾自动成文（v0.4 增补）

- **定位**：把「便签」和「日程」缝在一起的差异化能力——完成的待办、当天日程、当天课程、每日必做勾选，按天写成一篇本地 Markdown 笔记，进入笔记列表的「每日回顾」分类。
- **自动**：默认开启，次日首次启动时生成前一天的回顾（内容完整、不会反复改写）；当天完全没有记录时静默跳过，避免空笔记噪音；`lastReviewDay` 持久化去重。
- **手动**：每日必做分区提供「生成今日回顾」按钮，可对当天即时生成；同标题同分类的笔记走更新而非重复创建，并广播 `notes-changed` 让笔记工作区刷新。
- **边界**：课程按星期列出，不做周次过滤；回顾是快照，后续修改待办不会自动回写已生成的笔记。

### 6.15 桌面小窗（v0.5 增补）

- **两个独立窗口**：「今日日程」（当天日程 + 当天课程，课程取课表设置的起止时刻，按当前周过滤）与「今日待办」（逾期 + 今天到期 + 今天已完成），各自可固定到桌面；无边框、可拖动、默认置顶，可在小窗内切换置顶。
- **两种形式**：时间轴（时间刻度 + 竖线节点 + 卡片）与表格（时间 / 事项 / 信息三列），切换结果按窗口记住。必要信息：日程显示起止时刻与备注首行；课程显示上课时刻、地点、教师、周次；待办显示截止时间、标签、提交平台、优先级与逾期状态，可直接勾选完成。
- **空状态**：没有任何条目时窗口不空白，显示图标、明确文案（「今天没有安排」/「今天没有待办」）、说明与刷新按钮；底部常驻条目数与更新时间。
- **位置记忆**：拖动后把窗口位置与尺寸写入 `agenda/widgets.json`（随数据目录迁移），下次打开回到原处。
- **合并小窗（v0.13）**：日程与待办合并为一个 `agenda-widget` 窗口，**上下同时显示**——上半是今日日程（时间轴 / 表格可切换），下半是今日待办清单，两块各自滚动、各带标题与条数；待办区底部常驻 DDL 压力条，底栏汇总「日程 n 项 · 待办 m 项」与「明天有 N 节课」。窗口默认 420×720。启动 1.2 秒后自动恢复这一个窗口，位置沿用 `widgets.json` 的 `all`（兼容旧的 `schedule` 位置），否则放在屏幕右侧。`--silent`（开机自启）启动时不弹窗。
- **实时刷新**：监听 `agenda-changed` 自动重载；每分钟刷新当前时间与日期；主窗口改动后两个小窗同步更新。
- **入口**：日程工作区顶部「日程窗」「待办窗」按钮；命令 `open_agenda_widget` / `agenda_widget_bounds_get` / `agenda_widget_bounds_save`。
- **验收**：两个窗口可同时显示、切换视图不丢数据；无数据时有提示；关闭为隐藏（复用窗口），重新打开保留位置与视图。

### 6.16 智能排期、课程笔记与学习洞察（v0.7 增补）

- **智能排期**：纯函数 `planSchedule` 计算每天「08:00–22:00 减去课程与日程」的空档（课程后留 5 分钟缓冲），把未完成且有 DDL 的待办按「DDL 升序 → 优先级降序」贪心填入，时长取 `estimateMinutes`（默认 30 分钟，按 15 分钟取整）；停课例外会释放空档，逾期任务按今天处理。弹窗按日期分组、默认全选、可逐项取消，一键写为 `[计划] 标题` 日程（同标题同开始时间自动跳过）。
- **预估时长**：`Todo.estimateMinutes`（5–480 分钟），待办抽屉可选 15/30/45/60/90/120 分钟或未估算。
- **课程笔记归档**：课程抽屉「记笔记」按当前周生成 `第 N 周 · 课程名` 标题，分类为课程名（不存在则自动创建），正文带日期/地点/教师/周次与「课堂笔记」小节，创建后直接打开笔记编辑器。
- **DDL 压力曲线**：未来 14 天每天到期未完成待办数的柱状条，逾期单独计数；峰值日高亮，接入待办列表顶部与桌面待办小窗（紧凑模式）。
- **上课自动免打扰**：提醒引擎按课程表节次（含 5 分钟缓冲、当前周匹配、停课例外）判断是否在课堂上，课堂中不弹提醒；课后 30 分钟窗口内补发。可在提醒设置中关闭。
- **学期周次进度条**：课程表顶部显示「第 N / 总周数」与剩余周数，总周数从课程周次写法推断（默认 16）。
- **单次调课 / 停课**：`agenda/course_overrides.json` 保存某课程某天的例外（停课或调至其他节次/地点），课程表显示「停课/调课」标记，排期与周统计都会应用；同课程同天只保留一条。
- **A4 打印**：课程表「打印」打开白底 A4 横向视图，`@media print` 隐藏应用 UI，可直接打印或另存为 PDF。
- **本周时间账本**：课程模式「周回顾」汇总本周上课时长、日程时长、完成待办数、每日必做完成率与各课程未完成作业，写入「每周回顾」分类的 Markdown 笔记（同标题更新）。

### 6.17 双人课表（v0.9 增补）

- **第二个人档案**：昵称、关系（伴侣 / 兄弟姐妹 / 同学 / 朋友 / 其他）、颜色，独立存 `agenda/partner.json`，随数据目录迁移。
- **对方课程**：在「双人课表」弹窗里用文件导入（复用 `.xls/.xlsx` 解析器），或后续手动补充；对方课程只读，不参与提醒、智能排期与今日待办。
- **同表展示**：双人模式自动加大行高（每节 66px）。同一时间段内**双方课程都占满整个节次跨度**（不再压成半格）：自己的课程实色背景、实线左边框、文字靠上；对方课程淡化背景、虚线左边框、文字靠下，重叠时也能同时读出两人都占用该时段。网格顶部有图例：我 / 对方昵称 / 共同空档。
- **关系专属图标**：伴侣＝爱心、兄弟姐妹＝双人、同学＝学士帽、朋友＝交叠圆环、其他＝单人；用于课程块、月视图课程条、弹窗列表与关系选择按钮，一眼区分。
- 双方都没课的格子显示浅绿底与圆点作为「共同空档」。
- **显示与清除**：课程表顶部眼睛按钮一键显示/隐藏对方课表（状态本地记忆，不删数据）；双人弹窗内也可切换。弹窗「清空」可删除对方全部课程（保留昵称/关系/颜色），带二次确认。
- **清空本人课表**：课程表顶部垃圾桶按钮可一键清空本学期全部课程，同时清除调课例外，带二次确认。
- **共同空档**：按当前学期周次过滤双方课程后计算（7 天 × 12 节），周次不匹配的课程不占用空档。
- **月视图**：课程条按「课」标记显示，对方课程显示为「昵称 · 课程名」，点击打开双人课表设置。
- **验收**：导入对方课表后同一张表可见两人课程；共同空档只出现在双方都无课的节次；删除对方课程后网格与空档同步更新；对方数据不影响自己的提醒与统计。

## 7. 关键交互说明

### 7.1 待办完成的动效与撤销

点击勾选 → 勾选框填充竹绿色并打勾 → 标题划线 → 停留 1 秒（可在设置改为立即/保留）→ 淡出并移入「已完成」。期间右下角出现「已完成 · 撤销」Toast，5 秒后消失。撤销恢复原排序位置与 `completedAt = null`。

### 7.2 日历空白处新建

- 月视图点某天：打开事件抽屉，日期预填该天，默认 09:00–10:00（若当天已过则顺延到下一个整点）。
- 周视图在时间轴上拖选：预填起止时间，松手即打开抽屉。
- 抽屉内 `Ctrl+Enter` 保存，`Esc` 关闭；未保存内容关闭时二次确认。

### 7.3 提醒的生命周期

```
待触发 → 已排程 → (到点) → 已通知 → 用户处理
                                   ├── 完成待办 / 关闭事件 → 结束
                                   ├── 稍后提醒 → 重新排程
                                   └── 无操作 → 保留在通知中心，不再重复弹
```

排程去重键 = `kind + id + occurrenceStart + offset`，持久化最近 7 天，避免重启后重复通知。

### 7.4 空状态

- 待办为空：「今天还没有安排。按 N 记一条。」
- 日程为空：月视图正常显示网格，当天格内显示淡色「+ 添加」。
- 首次进入日程：一次性提示「点击任意日期即可添加」，可关闭且不再出现。

## 8. 边界与异常

| 场景                   | 预期行为                                                                 |
| ---------------------- | ------------------------------------------------------------------------ |
| 待办只有日期没有时间   | 按全天处理，列表显示「今天」而非「09:00」；提醒默认 09:00                 |
| 事件跨天               | 月视图拆成多段连续条；周视图在两天各占一段，跨天处不显示圆角             |
| 事件结束早于开始       | 保存时自动交换；若时长为 0 则补为 30 分钟                                |
| 重复事件修改           | P1 只支持「修改全部」；修改单次时提示「将在后续版本支持」                 |
| 系统时区变更           | 已存 UTC 时间按新时区重新渲染；全天事件不受影响                          |
| 通知权限被拒           | 降级为应用内 Toast + 托盘红点；设置页提供「去系统设置」说明               |
| 数据文件损坏           | 重命名为 `*.corrupt-<时间戳>.json` 后以空数据启动，并提示备份位置          |
| 多窗口同时修改         | 单进程内由 Rust 侧互斥锁串行化；写成功后广播 `agenda-changed`，各窗口刷新  |
| 数据目录迁移           | 日程数据必须随 `notes/images/backgrounds` 一起搬走，否则用户会认为数据丢失 |
| 一万条待办             | 列表虚拟滚动；首屏 < 300ms；搜索防抖 150ms                               |
| 系统时间被回拨         | 排程以单调时钟推进，检测到回拨超过 5 分钟时重算全部下次触发时间           |

## 9. 非功能需求

- **性能**：主窗口冷启动不增加网络请求；切换工作区 < 100ms；月视图滚动 60fps；通知延迟 ≤ 60 秒。
- **兼容**：沿用现有平台范围（Windows 10+、macOS 15+），100%–200% DPI 下布局不破。
- **隐私**：日程与待办不上传、不联网；除更新检查外无出站请求。
- **无障碍**：所有操作可键盘完成；焦点可见；颜色不作为唯一信息载体（优先级同时有文字/图标）；对比度符合 WCAG AA。
- **国际化**：zh-CN / zh-HK / en-US 三语同步；日期格式随语言变化，周起始日可独立配置。

## 12. 风险与开放问题

| 风险                         | 影响                                       | 应对                                                       |
| ---------------------------- | ------------------------------------------ | ---------------------------------------------------------- |
| 日历是范围黑洞               | 拖拽、重复、时区每一项都能无限投入         | P0 锁定「月 + 周 + 不重复」；重复与日视图进 P1/P2           |
| 提醒在便携版 Windows 失效    | 用户以为功能坏了                           | 检测无包身份时降级为应用内提醒，并在设置页说明              |
| 待办与笔记职责重叠           | 用户不知道该记在哪                         | 用「有时间块 = 日程，有截止 = 待办，其余 = 笔记」一句话引导 |
| 主窗口文件过大导致改造风险   | 引入回归                                   | 先机械拆分 `NotesWorkspace`，不改逻辑，再挂工作区切换       |
| 三语翻译量翻倍               | 发布前赶工导致漏译                         | 先冻结 key 清单，翻译与开发并行；CI 校验 key 完整性         |

**待确认**：

1. 「周起始日」默认周一还是周日？中文用户习惯周一，但 macOS 系统默认跟随区域。
2. 待办是否需要「清单/项目」二级分组，还是标签足够？本 PRD 先按标签设计。
3. 提醒是否要支持声音？当前倾向只做系统通知，避免用户反感。
4. 日程是否需要「全天事件跨天连续条」的视觉，还是逐日显示？前者好看但实现成本高。
